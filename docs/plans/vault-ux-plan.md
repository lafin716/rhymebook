# 보관함 UI/UX 개편 계획 (IMP-26, ADR-058)

모드: Scoped feature (보관함 화면 한 영역 + core 페이지 블록 모델). 난이도 MEDIUM–HIGH(포인터 드래그·레이아웃 모델). 실행: 현재 모델(Opus 5.5) 직접 구현, 별도 리뷰 에이전트로 독립 검토.

## 목표 / 완료 기준
1. 태블릿·데스크톱(≥768)에서 보관함 기본 높이 화면 80% — 원인: `cn`이 단순 결합이라 Modal의 `md:h-auto`와 `md:h-[84vh]`가 충돌. Modal `size: 'auto' | 'tall' | 'full'`로 해결.
2. 닫기 왼쪽 [전체 화면]/[창으로] 토글(≥768에서만, 기기별 localStorage `branch.vaultFull`).
3. 트리 항목 드래그로 폴더 이동(마우스: 6px 이동, 터치: 길게 눌러 끌기). 맨 위로 놓기 영역 제공. 자기·하위 폴더로는 불가.
4. 상세의 '옮길 폴더' select 삭제 → [이동] 버튼 → 폴더 트리 선택 창.
5. 상세 상단 도구 모음: 페이지에 넣기(페이지 선택 창), 이동, 복사(글: 클립보드 / 이미지: 이미지 저장), 지우기, 수정하기(이름·글 내용 편집 후 저장/취소), 원래 대화 열기. 폴더·페이지에도 해당하는 버튼만.
6. 페이지: 편집은 로컬 초안 → [저장]으로만 반영, [취소]/다른 노드로 이동/닫기 시 변경 있으면 확인.
7. 페이지 블록: 손잡이 드래그로 순서 변경(위/아래 버튼 유지), 다른 블록의 왼쪽/오른쪽 가장자리에 놓으면 나란히(한 줄 최대 3칸). [나란히 풀기] 버튼. 768px(md) 미만에서는 세로로 쌓는다.

## 데이터 계약 (core)
- `VaultPageBlock`에 선택 필드 `beside?: true` — 앞 블록과 같은 줄. 없으면 새 줄(구 데이터 그대로 호환).
- `isVaultNode`가 `beside: true`만 허용. 첫 블록의 beside, 한 줄 4칸 이상은 `normalizePageBlocks`로 정리.
- 순수 함수: `pageRows`, `normalizePageBlocks`, `placeVaultPageBlock(page, id, targetId, 'before'|'after'|'left'|'right')`, `unsetBeside`. 위/아래 이동은 자리(줄 모양)를 유지하고 내용만 바꾼다. 블록 제거 시 줄 시작이 빠지면 다음 블록이 줄을 시작.
- 옛 호스트(0.16.0)는 beside를 모르면 `invalid` → 클라이언트가 'outdated'로 안내(ADR-057).

## 유지할 동작
- 모바일 목록↔상세 전환, 기존 보관 진입점, Markdown 저장, 동기화 op 형식.

## 검증
- core 단위 테스트(레이아웃 함수·검증), e2e vault.spec 갱신(이동 창·저장 버튼·나란히·드래그), typecheck/lint/test/e2e, 768·1024·모바일 스크린샷, 데스크톱 앱 재빌드.
