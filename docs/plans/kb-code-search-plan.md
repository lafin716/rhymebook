# 지식베이스 코드 찾기·상세 속도 개선 계획 (ADR-119)

## 문제 (쿠버네티스 저장소 클론·색인 후)
1. 지식베이스 상세가 색인된 문서 전부를 불러와 검색 목록으로 그린다 → 큰 저장소에서 느림.
2. "기능 X의 소스 코드 찾아줘"에 "작업 폴더를 검색·읽는 도구가 없다"며 엉뚱한 발췌를 인용하고 일반 지식으로 답함.

## 원인
- 상세 `DocsPanel`이 `listDocs` 전체를 그린다.
- bridge `index()`가 채팅마다 KB 폴더 전체(2만+ 파일)를 걷고 경로를 프롬프트에 넣는다(상한에서 잘림).
- Claude CLI는 임시 cwd + `--add-dir`인데, 안내문에 KB 절대 경로가 없어 Glob/Grep이 cwd를 뒤진다.
- Codex는 파일 도구가 없는데 안내문이 "파일 내용 미제공"만 말해 모델이 도구 부재를 사과한다.
- 한국어 질문과 영어 코드가 맞지 않는다(로컬 해시 임베딩·FTS·심볼 검색 모두 어휘 기반).

## 범위
| ID | 내용 | 소유 |
|---|---|---|
| K1 | 상세에서 문서 목록 패널 제거(i18n `knowledge.docs` 삭제, e2e 갱신) | ui |
| K2 | bridge `outline()` — 깊이 3 BFS 폴더 개요(숨김·심볼릭 제외, 상한·잘림 표시) | bridge |
| K3 | Claude·Codex 안내문 재작성: KB 절대 경로, 절대 경로로 Glob/Grep/Read, 영어 식별자로 grep, Codex는 발췌 근거·못 찾음 안내 | bridge·i18n |
| K4 | core `rag/expand.ts` 질의 확장 + store 연결(8초 제한, 실패 시 원래 계획, 토큰 필터·핵심어 상한) + 설정 `expandQuery` | core·ui |
| K5 | 테스트·검증·리뷰·데스크톱 재빌드·문서 | 리더 |

## 유지할 동작
- 출처 패널·RAG 설정·임베딩 설정은 그대로. `listDocs` API는 다른 곳(원격 등)을 위해 남긴다.
- 확장 요청은 도구·웹·지식베이스 없이(`purpose: 'search'`). 영어 질문은 확장하지 않는다.

## 검증
`pnpm typecheck && pnpm lint && pnpm test`, `pnpm e2e`, 데스크톱 package:dir 재빌드 후 실행.

## 실행 메모
난이도 MEDIUM, 리더(현재 Claude 모델) 직접 구현, 독립 리뷰는 별도 에이전트.
