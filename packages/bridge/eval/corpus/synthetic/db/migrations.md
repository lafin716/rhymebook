# 데이터베이스 스키마 마이그레이션

스키마 변경은 버전 번호가 붙은 마이그레이션 파일로 관리한다. 배포 때마다 아직 적용되지 않은 파일만 순서대로 실행한다.

## 원칙
- 한 번 적용한 파일은 고치지 않는다. 바꿀 내용은 새 파일로 추가한다.
- 컬럼 삭제나 이름 변경은 두 단계로 나눈다. 먼저 새 컬럼을 추가해 코드가 둘 다 쓰게 하고, 나중에 옛 컬럼을 지운다.
- 큰 테이블에 인덱스를 만들 때는 잠금이 없는 방식(예: PostgreSQL `CREATE INDEX CONCURRENTLY`)을 쓴다.

## 실패 처리
마이그레이션이 중간에 실패하면 트랜잭션을 되돌린다. 되돌릴 수 없는 DDL이 섞였다면 수동 복구 절차를 `ops/` 문서에 적어 둔다.

## 기록
적용 이력은 `schema_migrations` 테이블에 버전과 체크섬을 남긴다. 체크섬이 다르면 실행을 멈춘다.
