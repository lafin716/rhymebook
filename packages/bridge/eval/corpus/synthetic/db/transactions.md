# 트랜잭션 격리 수준

트랜잭션 격리 수준은 동시에 실행되는 트랜잭션이 서로의 중간 결과를 얼마나 볼 수 있는지 정한다.
낮을수록 빠르지만 이상 현상이 생기고, 높을수록 안전하지만 충돌과 재시도가 늘어난다.

## 네 단계
- READ UNCOMMITTED: 커밋되지 않은 값도 읽는다(dirty read). 거의 쓰지 않는다.
- READ COMMITTED: 커밋된 값만 읽는다. 대부분의 DB 기본값이다.
- REPEATABLE READ: 같은 트랜잭션 안에서 같은 행을 다시 읽으면 값이 같다.
- SERIALIZABLE: 동시 실행 결과가 어떤 순차 실행과도 같아지도록 한다. 충돌하면 한쪽을 되돌린다.

## 실무
직렬화 실패(serialization failure)가 나면 애플리케이션이 트랜잭션을 처음부터 다시 실행해야 한다.
결제처럼 돈이 오가는 작업은 SERIALIZABLE 또는 행 잠금(SELECT ... FOR UPDATE)을 쓴다.
